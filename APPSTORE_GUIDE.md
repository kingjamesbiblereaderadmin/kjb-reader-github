# iOS App Store Publishing Guide

The iOS app is built the same way as the Android app: a native **Capacitor** shell
(`ios/`) that loads the live site (`https://kingjamesbiblereader.com`) in a WKWebView,
with the Capacitor bridge injected so native plugins (Share, Screen Orientation, App
lifecycle) work on the live site exactly as they do inside the Android shell.

**Project details**

| Item | Value |
|---|---|
| Project | `ios/App/App.xcworkspace` (scheme `App`) |
| Bundle ID | `com.kingjamesbiblereader.twa` (matches the Capacitor config; must stay identical across releases) |
| Display name | KJB Reader |
| Version | 1.74 (build 75) — kept in sync with the Android build per release |
| Deployment target | iOS 13.0 |
| Orientations | Portrait + landscape (matching the Android app's Auto Rotate) |
| Web content | Live site (remote-URL mode) — `capacitor.config.json` is generated by `npx cap sync ios` |

---

## 1. Prerequisites (one-time)

1. **A Mac** running macOS 14+ with **Xcode 15+** (App Store submissions require a
   recent Xcode; check the currently accepted version at
   https://developer.apple.com/support/xcode/).
2. **CocoaPods**: `brew install cocoapods`
3. **Apple Developer Program** enrolment — https://developer.apple.com/programs/
   (US$99/year). This gives you the App Store Connect account, signing
   certificates, and submission rights.

## 2. First local build

Run from the repo root on the Mac:

```bash
npm install
npm run build                 # cap sync needs the web build (webDir) even in remote-URL mode
npx cap sync ios              # generates ios/App/App/capacitor.config.json + Pods
cd ios/App && pod install && cd ../..
npx cap open ios              # opens App.xcworkspace in Xcode
```

In Xcode:

1. Select the **App** scheme and your device/simulator.
2. Under **Signing & Capabilities**, set your **Team** (signing style is already
   Automatic).
3. Run once on a real iPhone to sanity-check the notch/safe areas, share sheet,
   and the live site loading.

## 3. App icon (required before submission)

The template ships a placeholder icon. Replace
`ios/App/App/Assets.xcassets/AppIcon.appiconset/AppIcon-512@2x.png`
with your own square logo exported at **1024×1024 px, PNG, no alpha channel**
(Xcode's single-size icon — no other sizes needed). Keep the filename the same
so the asset catalogue picks it up.

The splash (`Splash.imageset`) can be customised the same way later; the
template splash is accepted.

## 4. App Store Connect setup (one-time)

1. **Register the Bundle ID**: App Store Connect → *App IDs* → register
   `com.kingjamesbiblereader.twa` (or let Xcode's automatic signing create it).
2. **Create the App record**: My Apps → ➕ → *New App* → Platform iOS, name
   **KJB Reader**, language English, bundle ID as above, SKU e.g.
   `kjb-reader-ios`.
3. **App information**: Category *Books* (secondary *Reference*). Age rating
   questionnaire — nothing objectionable in a Bible reader.
4. **Privacy**: The app offers account sign-in (email/Google via Base44) and
   stores user content (saved verses, settings, reading progress) against that
   account — declare "Account info" (email address) and "User content" as
   collected, linked to identity. Analytics events are minimal and anonymous.
5. **App Review information**: provide a demo account if your review build
   requires sign-in for any visible feature, plus contact details.
6. **Screenshots**: needed per device size — 6.7" (1290×2796), 6.5"
   (1242×2688), and iPad (2048×2732) if you support iPad (the project is
   universal). The existing marketing screenshots can be reused/re-exported.

## 5. Building & uploading

**From Xcode (simplest):** `Product → Archive`, then
`Window → Organizer → Distribute App → App Store Connect → Upload`.

**From CI (GitHub Actions):** the workflow below mirrors
`build-android.yml`. Because agent tooling can't write to `.github/workflows/`,
add this manually as `.github/workflows/build-ios.yml` (copy from
`ios/ci/build-ios.yml` in this repo, same content):

- **Repository secrets to set:**
  - `APPLE_TEAM_ID` — found at https://developer.apple.com/account → Membership
  - `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8` (base64 of the .p8) — an App
    Store Connect **API key** (App Store Connect → Users and Access →
    Integrations → Team keys, role *App Manager* or higher). Xcode uses this
    key for `-allowProvisioningUpdates` (fully-automatic signing, no cert
    files to manage) and `fastlane` uses it to upload.

```yaml
name: Build iOS App
on:
  workflow_dispatch:
  push:
    branches: [main]

jobs:
  build:
    runs-on: macos-14
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - uses: maxim-lobanov/setup-xcode@v1
        with: { xcode-version: '16.1' }
      - name: Install deps
        run: npm install
      - name: Build web + sync
        run: npm run build && npx cap sync ios
      - name: Install pods
        run: cd ios/App && pod install
      - name: Write signing key
        run: |
          mkdir -p ~/.appstoreconnect/private_keys
          echo "${{ secrets.ASC_KEY_P8 }}" | base64 -d > ~/.appstoreconnect/private_keys/AuthKey_${{ secrets.ASC_KEY_ID }}.p8
      - name: Archive
        run: |
          xcodebuild -workspace ios/App/App.xcworkspace -scheme App \
            -configuration Release -sdk iphoneos \
            -destination 'generic/platform=iOS' \
            -archivePath build/App.xcarchive \
            -allowProvisioningUpdates \
            -authenticationKeyPath ~/.appstoreconnect/private_keys/AuthKey_${{ secrets.ASC_KEY_ID }}.p8 \
            -authenticationKeyID ${{ secrets.ASC_KEY_ID }} \
            -authenticationKeyIssuerID ${{ secrets.ASC_ISSUER_ID }} \
            DEVELOPMENT_TEAM=${{ secrets.APPLE_TEAM_ID }} \
            CODE_SIGN_STYLE=Automatic
      - name: Export IPA
        run: |
          xcodebuild -exportArchive -archivePath build/App.xcarchive \
            -exportOptionsPlist ios/ci/ExportOptions.plist \
            -exportPath build/ipa \
            -allowProvisioningUpdates \
            -authenticationKeyPath ~/.appstoreconnect/private_keys/AuthKey_${{ secrets.ASC_KEY_ID }}.p8 \
            -authenticationKeyID ${{ secrets.ASC_KEY_ID }} \
            -authenticationKeyIssuerID ${{ secrets.ASC_ISSUER_ID }}
      - name: Upload to App Store Connect
        run: fastlane deliver --api_key_path ios/ci/asc_key.json --ipa build/ipa/App.ipa --skip_screenshots --skip_metadata
```

Supporting files created in `ios/ci/`:
- `ExportOptions.plist` (App Store export, automatic signing)
- `asc_key.json` template for the fastlane upload step (fill from the same
  secrets during the run — see the file's comments)

## 6. Per-release checklist

1. Bump `ios/App/App.xcodeproj/project.pbxproj` → `MARKETING_VERSION` and
   `CURRENT_PROJECT_VERSION` (keep in lockstep with the Android build:
   currently **1.74 (75)**).
2. Archive & upload (Xcode or CI).
3. In App Store Connect: create a version, add release notes, pick the new
   build, submit for review. First review typically takes 24–48 hours.

## 7. Review risk — read before submitting

Apple guideline **4.2 (Minimum Functionality)** sometimes rejects apps that are
thin wrappers around a website. The Android shell passes Google's equivalent
because of native value: the **offline-fallback bundle**, native share, native
orientation control. The iOS shell currently has the plugins but **no offline
bundle** — it needs internet on first launch and after every cold start without
connectivity. Before submitting, it is strongly recommended to port the
offline-fallback approach to iOS (bundled `bible`/`fonts`/`images` assets in
`ios/App/App/public/` + a WebViewAssetHandler / `WKURLSchemeHandler`), and to
mention the offline capability and native integrations in the review notes.
